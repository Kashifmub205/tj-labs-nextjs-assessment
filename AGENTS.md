# Project Instructions

- Write clean, production-quality TypeScript and React/Next.js code.
- Keep implementations simple, readable, focused, and easy to explain in an interview. Prefer conventional React patterns over clever solutions.
- Use components when there is genuine reuse or a clear responsibility boundary. Keep them reasonably small; do not split files merely to create components.
- Use clear, conventional names for files, components, functions, variables, and props. Keep imports and files organized.
- Avoid unnecessary abstractions, wrappers, helpers, hooks, configuration, defensive code, and type complexity. Do not use `any` without a strong reason.
- Add dependencies only when they are necessary and provide a clear benefit for the assessment.
- Comment only to explain non-obvious decisions or constraints. Do not leave TODOs, placeholder comments, generated-looking explanations, dead code, or emojis in source, documentation, commits, comments, or UI unless the supplied design includes them.
- Keep styling organized and avoid duplicated CSS where reasonable. Match supplied Figma designs accurately; do not improvise visual details.
- Preserve semantic HTML and accessibility where appropriate.
- Do not make unrelated refactors while implementing a focused task.
- Run relevant type, build, or test checks after meaningful changes.
- AI assistance will be disclosed honestly in the README as required by the assessment. Prioritize professional engineering quality rather than concealing AI usage.
